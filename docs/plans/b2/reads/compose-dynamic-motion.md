# compose-dynamic-motion: the B1 Python motion engine (aadhi/compose/dynamic/**, aadhi/compose/motion/**, scripts/bench_motion.py), plus how the render_video job switches engine (aadhi/compose/video.py and aadhi/jobs/**)


## summary
This slice turns a Dynamic timeline (Timeline.presentation.style == "dynamic") into an MP4. Every frame is captured from the web stage (/render-dynamic, window.aadhiStage v3) in headless Chromium, encoded per chunk with x264, then joined, muxed and checked. There are two packages. aadhi/compose/dynamic/ holds the QA gates and the shared Playwright page driver: colour.py parses CSS colours and computes WCAG contrast; stage_page.py drives the stage page (network policy, token in the URL fragment, CDP JPEG capture, error and guard-trip collection); preflight.py runs the textBoxes() checks and their automatic remedies before capture; container.py runs the post-render container checks with their remedies and builds Render.options["qa"]; determinism.py holds the frame-hash plans and the spot check. aadhi/compose/motion/ is the engine: chunks.py (frame bounds, the 240-600-frame chunk planner, the cache key), cache.py (the content-addressed chunk store in the workspace), encode.py (pure ffmpeg argument builders), media.py (mediaPlan validation and frame mapping), resources.py (the cgroup-aware worker count and host-wide flock/msvcrt CPU slots), stage.py (StageSession: one Chromium per worker, page recycling, the /__frames route), engine.py (render_motion, which orchestrates everything) and job.py (render_dynamic, the job branch: preflight, then the engine, QA and storage). The engine switch is not in aadhi/jobs. It is in aadhi/compose/video.py:999-1005, inside the @job_handler("render_video") handler, keyed on job.timeline.presentation.style. The timeline only gets a presentation when DYNAMIC_ENABLED is on (aadhi/compose/timeline.py:731), so the dynamic_disabled check at job.py:110 is defensive. End-to-end flow: render_video opens a RenderWorkspace (render-<id>/ with a fresh attempt dir) and builds the timeline. render_dynamic then checks capabilities and free disk, picks caption modes, mints a 4 h render token, resolves the served timeline (URLs filled) and runs run_preflight. Preflight uses one browser and 1x1 placeholder media frames. It samples 24 spread frames, the first and last frame of every scene, every beat's settled frame and, in 9:16, every caption-chunk start, and evaluates textBoxes(). It plans remedies (shrink, safe_variant, scrim), applies them to a copy of the served timeline, reloads and re-checks the touched scenes, then finalises the statuses. A blocking result stores the preflight QA and raises PreflightBlocked (code preflight_blocked). render_motion then plans the chunks and starts the audio master task (the classic narration, tick and ding mix, the ducked BGM, AAC 384k) concurrently. It pre-fetches the narration and video media, takes up to W CPU slots, starts one StageSession per slot (sharing one Playwright driver) and checks info() against the timeline. It computes a chunk key per chunk; workers take chunks longest first, reuse cached chunks, or run mediaPlan, extract the media frames with ffmpeg, then seek and CDP-JPEG every frame into an x264 MPEG-TS pipe and verify the packet count. Finally it concatenates the chunks and muxes with the master audio (-c copy, chapters, optional mov_text, +faststart+negative_cts_offsets) and runs verify_container with the rerender_chunks, reencode_audio and remux remedies. render_dynamic stores the MP4/SRT/VTT as assets with qa = motion_qa(container, preflight) plus qa.motion. B1 matches the design doc's 'built and integrated' status. The B2 and B3 modules (themes.py, textfit.py, zones.py, kinetic.py, direct.py, events.py, mix.py, casting.py, history.py, music providers) do not exist yet, and the engine still uses the classic audio mix.

## contracts

Stage contract v3. window.aadhiStage = {version 3, ready -> {webgl}, info() -> {width, height, fps, frames, scenes:[{index, f0, f1}]}, mediaPlan(f0, f1), seek(frame) -> {key}, textBoxes(), setLayers({captions, stage})}. 12. Master audio: AAC-LC 48 kHz stereo 384k, -t total_seconds. Final mux: concat -c copy plus the m4a -c copy, -map_metadata and -map_chapters from ffmetadata, mov_text with default disposition and language, -t total, -movflags +faststart+negative_cts_offsets.
13. Media extraction: -ss max(0,(first-0.5)/rate) before -i, scale=w:h:force_original_aspect_ratio=increase:flags=bicubic, -q:v 3, -start_number first, f_%06d.jpg (encode.py:133-155). Page index n maps to file frame floor(n*rate/srcFps + 1e-6) (media.py:126-136).
14. Errors. MotionError(code, retryable) codes: not_dynamic, empty, asset_missing, asset_unreadable (retryable), stage_contract, media_missing, media_unreadable, bad_payload, chunk_frames (ChunkCountError, retryable). StageError codes: render_page_* (boot), render_page_timeout, render_page_http, render_page_not_ready, render_page_script_error, stage_contract, stage_call_failed, stage_crashed (retryable), stage_capture_failed (retryable), stage_closed, stage_refresh_failed (retryable), render_network_policy, render_unavailable, config. ContainerCheckFailed has code render_invalid. job._job_error maps retryable errors to RetryableJobError (the code is lost) and others to FatalJobError(code) (job.py:93-97).
15. Invariant: one render never mixes engines (video.py:999-1005). Classic timelines never import compose/motion or compose/dynamic.

## conventions
- Every module opens with a long docstring citing DYNAMIC_VIDEO_DESIGN sections (§7.x), rule ids (R-29, R-53, R-59) and research tags ([MR C11], [RV E-5]). Comments explain why, often with measured numbers (encode.py:15-18, engine.py:969). New code should keep this style and keep docs in sync (ARCHITECTURE.md §14, INTERFACES.md:373-410, API.md:105-118, OPERATIONS.md), which is a batch gate (§10.2 item 5).
- The line length is about 120 characters. Code uses `from __future__ import annotations`, dataclasses (frozen for value types), keyword-only arguments, and explicit `__all__` in engine.py and stage.py.
- Blocking work (file I/O, DB, link/copy, rmtree, psutil, bundle_digest, slot locks) always goes through `asyncio.to_thread`. ctx.session(), progress and log are used as JobContext defines them (jobs/base.py:84-134). Cancellation is polled with ctx.check_cancelled between frames, inside await_polling (stage_page._Deadline) and inside run_ffmpeg.
- Errors carry `code` and `retryable`. Contract violations are never retried; crashes and timeouts are retryable. User-facing messages are plain teacher English (preflight _MESSAGES :105-116; the 'Shorten text' action). Every message from a page or ffmpeg passes through settings.redact and is truncated (stage_page._note :229-234, _call :323).
- Pure builders are separate from I/O (encode.py returns argument lists and Command(args, files); chunks.py is pure except bundle_digest; media.py is pure except Path.is_file). Tests exercise the pure parts directly.
- Determinism rules: every frame is a pure function of (timeline, frame); there are no fixed sleeps or page.clock, and CSS animations are frozen via CDP. The x264 thread count is fixed so that bytes are reproducible. Chunk keys hash content addresses, never URLs. Extraction happens at the file's native rate (never an fps filter). Captures are CDP JPEG q92 with optimizeForSpeed.
- Files are published atomically: a temporary '.<name>.<tag>.part' file, then os.replace, then the marker written last (cache.py:84-103, mirroring workspace.py).
- Content-addressed reuse: a cached chunk is used only when its marker frames and bytes match AND its packet count (ffprobe packet_pts) equals the frames.
- Python's chunk sizes, zones and type floors mirror JS constants (preflight bands = web/js/dynamic/core.js:360-387; caption size and min at captions.js:108-111). Change both sides together.
- Tests: tests/compose/dynamic/* and tests/compose/motion/* with stub stages (stub_stage/, stage_server.py); slow engine tests are suffixed _slow; the determinism and container suites are in tests/determinism (Docker test image, AADHI_CONTAINER_TESTS). A source-scan test guards STAGE_TIMELINE_FIELDS (test_chunks.py:197-213).
- Settings come from aadhi.config.Settings fields with pydantic bounds. The engine reads them via getattr with defaults where they are optional (resources.py:175, :183, :191).

## dynamic_status
B1 Python scope is implemented and matches the design's 'built and integrated' status (DYNAMIC_VIDEO_DESIGN.md:2459-2526): the worker pool, cgroup-aware W, host slots, CDP capture, chunk planner, encoder pipe, concat, mux with negative_cts_offsets, media extraction through route.fulfill, chunk cache keys, page recycling, the preflight framework, container checks with remedies, the engine switch, DYNAMIC_ENABLED, the motion compose profile (docker-compose.yml:142-175) and the benchmark harness. Nothing of B2 or B3 exists on the Python side: no aadhi/compose/dynamic/{themes,textfit,zones,kinetic,mix}.py, no aadhi/pipeline/{direct,events,casting,history,music}.py, no providers/music, and no web/dynamic/ directory. web/js/motion/ exists (color, count, draw, easing, random, text, track).

Divergences between code and docs/DYNAMIC_VIDEO_DESIGN.md:
1. §7.1 says preflight runs first and then the engine is picked. In code the engine is picked first (video.py:999-1005) and preflight runs inside render_dynamic (job.py:131-144).
2. §7.11 says the master audio is encoded and measured in preflight. In code it is built concurrently with capture inside render_motion (engine.py:943-947, waited at :1008) with the classic mix (narration, tick, ding, branding BGM ducked; engine.py:482-540). No loudness target is passed to inspect_container (engine.py:1039-1042), so R-48 loudness and true peak are never checked. timeline.music, timeline.sfx, VisualEvent.sfx and TimedOverlay.sound are ignored by the audio.
3. §7.6 says 'a retry or a one-scene edit re-renders only the chunks it touches'. In code the cache lives in render-<id>/chunks and is deleted on success (video.py:1006, 1031), so only retries reuse chunks (a documented deviation). total_duration in the global slice (chunks.py:43-44) also means any duration change invalidates every chunk.
4. §7.6 describes the bundle hash as web/js/dynamic, web/js/motion, dynamic.css, fonts and the vendor manifest. Code hashes all of web/js, web/css, web/vendor, web/dynamic and render-dynamic.html by size and mtime, not by content (chunks.py:41, :152-177).
5. §7.12 preflight implements only text_overflow, safe_zones, contrast and the added type_floor check (preflight.py:101). Duration profile, Aadhi time, the 9:16 frame-0 hook band, licences, music under speech, master loudness and caption re-chunking are missing; the docstring defers them at :44-46. Sampling adds scene last frames and beat-settled frames (:430-462), as documented.
6. §7.12 post-render warnings: pixel contrast with an automatic scrim re-render, static stretches and the 3-frame determinism spot check are missing. Only black edges are checked (container.py:22-23, :378-393). determinism.spot_check and spot_frames exist but nothing in production calls them.
7. §7.5: the 'second version' (clean master plus a caption-only PNG layer overlaid) and draft renders (CRF 23, 720p) are not implemented. StagePage.capture_png(transparent) exists (stage_page.py:377-385) but is unused. -threads 4, -frames:v and -protocol_whitelist were added to the encoder (documented).
8. §7.3 contract extensions: mediaPlan entries add asset_key (plus url, duration and end_behavior per web/js/dynamic/media.js:8). textBoxes adds scene, slot, size, weight, min, text and alpha. The /__frames chunk segment is optional (stage.py:47).
9. §7.4 rule 3: in a production render a guard trip is only a warning (engine.py:1000-1002); only tests fail on trips.
10. §7.6 workers: the code also bounds W by sched_getaffinity (resources.py:139-147, 163-170) and uses msvcrt.locking on Windows (:200-232). These are additions.
11. §7.8: WebGL flags exist (stage_page.py:56; StageOptions.webgl) but nothing sets webgl=True. Preflight never passes webgl. The WebGL probe result is only recorded (MotionResult.webgl; preflight webgl).
12. §7.3: 'mediaPlan... Aadhi clips extracted once per clip... cached as branding derivatives'. Not built. Aadhi ('aadhi' kind, ResolvedLook.presenter.clip_key) frames would be extracted per chunk like any clip, and B1's presentation.py sets no presenter.
13. Preflight bands: R-59 is approximated with fixed bands (preflight.py:75-82) that duplicate web/js/dynamic/core.js:360-387 (values equal today) until B2 zones.py.

## bugs_or_risks
1. CONFIRMED BUG: preflight duplicates findings across rounds. In _finalise (preflight.py:590-619), a first-round finding whose status is already 'warn' (type_floor, decorative overflow) or that has no remedy is appended without popping its ident from `again`. If the scene was touched by a remedy, the second round sees the same finding again, and the leftover loop at :616-618 appends it a second time. Verified with a snippet: first=[shrink headline, open body overflow (no remedy), warn type_floor] in scene 1, second=[body overflow, type_floor], planned={shrink 1 headline} gives [('text_overflow','headline','fixed'), ('text_overflow','body','block'), ('type_floor','chip','warn'), ('text_overflow','body','block'), ('type_floor','chip','warn')]. Effects: duplicated items, problems and warnings in Render.options['qa'], doubled check counts in check_status (:529-536), and duplicate job-log lines (job.py:138-141). Fix: pop again[f.ident] for every first-round finding, not only for remedied ones.

2. CONFIRMED RISK: preflight never sets the captions layer. run_preflight receives captions=burn (job.py:133-134) but never calls page.set_layers (preflight.py:690-717; grep shows set_layers is only called from motion/stage.py:201). In render mode the page defaults to layers.captions = presentation.captions_burn (web/js/dynamic/stage.js:376), and the Studio always sends burn_captions (aadhi/api/routers/renders.py:50-59; web/js/studio/views/projectDetail.js:302), which wins over the presentation (job.py:63-64). Two failure cases follow:
   (a) request burn=true with presentation captions_burn=false: preflight never sees caption boxes, so caption overflow, zones and 7:1 contrast go unchecked, while the band is still treated as taken.
   (b) request burn=false with presentation captions_burn=true: caption boxes are checked. A caption overflow at its floor (captions.js:111 reports min=size) blocks the render with 'Shorten text' even though no captions will be burned.
   Fix: call `await page.set_layers(captions=burned, stage=True)` after each load.

3. Container remedies are identical re-runs. remux re-executes the same mux command with the same inputs (engine.py:851-854, 882-885), and reencode_audio re-runs the identical classic mix (:874-880). A deterministic defect (wrong tags, start offset, A/V offset, a silent track) therefore survives its remedy and ends as render_invalid after the extra work. Only transient corruption can be fixed. The chunk check is also nearly unreachable, because _capture_chunk and cache reuse already verify packet counts (:724-726, :760).

4. A remedy capture runs without a CPU slot. The lease is released at engine.py:1003-1004 before verify_container, but rerender_chunks launches a new Chromium plus encoder (:856-872). Preflight's browser (job.py:133) also runs before any slot is taken. Both can oversubscribe a host shared by several renders.

5. Capture timing and resource hold include the audio master. gather_or_cancel waits for every task, including _audio_guard (engine.py:992-993; aio.py:76-86). If the AAC master is slower than the capture (short videos), all browsers and slots stay held until it finishes, and timings['capture'] and aggregate_fps (:230) absorb that wait.

6. Job-level FFmpegError is fatal. An encoder, extraction or mux failure that survives the single chunk retry becomes FatalJobError render_failed (video.py:1020-1023), so the chunk cache is never used by an automatic retry in that case. Only retryable Stage or Motion errors requeue (job.py:93-97; JOB_MAX_ATTEMPTS default 2, config.py:119). RetryableJobError also drops the specific code (job.py:96).

7. Bundle digest by mtime (chunks.py:152-177). If a deploy keeps file sizes and normalises mtimes (reproducible image builds, SOURCE_DATE_EPOCH), a stage change between two attempts of the same render could reuse stale chunks. The window is limited to RENDER_KEEP_FAILED_HOURS. Host fonts outside web/vendor are not in the key either.

8. The second preflight round re-scans only frames whose own scene was touched (preflight.py:709). A remedied finding seen only on another scene's frame (an outgoing-scene box during a transition, box.scene=X at frame scene X+1) is marked 'fixed' without being re-verified (:613-615). This is low probability because the scene's last frame is also sampled.

9. Failed page loads leak pages. StageBrowser.open appends the page before load and does not close it when load or _send fails (stage_page.py:452-461). After recycle failures, orphan pages stay in the browser until it closes.

10. Media cleanup on early failure. In _capture_chunk the try/finally that clears the FrameRegistry and deletes media_dir starts only after encoder.start() (engine.py:702-722). A mediaPlan, extraction or encoder-start error leaves extracted frames on disk until the attempt dir is removed.

11. If the page returns an empty scenes list, scene_mismatch passes (stage.py:118-121: `if got and ...`). Only the total frame count is checked.

12. Only sessions[0].info() is validated (engine.py:977-981). Other workers are assumed to have the same layout.

13. bench_motion.py reads the environment (Settings(_env_file=None) still reads env vars, :301). A set RENDER_BASE_URL overrides the static server, because base_url is set but render_origin prefers RENDER_BASE_URL (screenshot.py:162-166; bench :344).

14. When rounding gives a scene zero frames, scene_frame_bounds forces at least one frame per scene (chunks.py:79-80). That shifts later boundaries and makes the page's info disagree, which fails with stage_contract. This is an edge case for very short scenes.

15. The 4 h render token (job.py:42) is only used for the timeline request, which is answered locally (stage_page.py:423-426). It is not a problem today, but it would become one if B2 or B3 pages fetch authenticated app endpoints during long renders.
