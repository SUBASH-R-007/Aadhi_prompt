The eval harness (python -m aadhi.evals) runs the real pipeline stages in an isolated SQLite and storage workspace with forced fakes. It writes report.json/md, diffs runs and optionally judges with an LLM. evals/render_parity.py does classic preview-vs-MP4 grid diffs and Dynamic live-stage-vs-MP4 SSIM, and its dynamic_timeline() is the shared Dynamic QA fixture for about 15 test modules. First, the documented benchmark command cannot run in the app image, which blocks the last B1 acceptance item. Second, presentation.captions_burn can never take effect through the render API.

## conventions
- Docs: plain words; every claim names the code path. On conflict the contract file (schemas, base.py, config) wins (ARCHITECTURE.md:3-6), and code wins over SECURITY.md (SECURITY.md:5).
- Every batch updates ARCHITECTURE, INTERFACES, API, PROMPTS and OPERATIONS for its contracts (design §10.2 gate 5, DYNAMIC_VIDEO_DESIGN.md:2350). Batch status and 'As built' deviations are recorded in the design doc's batch section (e.g. 2386-2437, 2459-2526).
- Each design rule is cited by id (R-xx) and evidence key ([LS §x], [RV E-n]).
- New settings go in aadhi/config.py with a trailing inline comment, inside a '# --- Section ---' block, so gen_env_example.parse_comments picks them up (gen_env_example.py:91-116). Then regenerate .env.example (CI --check).
- Secrets are SecretStr and are emitted empty. Compose-only variables live in COMPOSE_SECTION (gen_env_example.py:58-81).
- Generated artifacts must be byte-for-byte reproducible and have a --check mode: LF newlines (newline='\n'), sorted output, fixed metadata (make_fixtures FIXED_DATE). Scripts insert ROOT into sys.path and use argparse with main(argv) -> int.
- evals/ is not a package. Load video_qa.py and render_parity.py by path with importlib.util.spec_from_file_location (video_qa.py:18; tests/compose/dynamic/helpers.py:43-44).
- Eval metrics are pure, with no I/O, randomness or clock (metrics.py:1-11). Percentages are 0-100 and None on a zero denominator. Headline metrics carry a direction.
- The eval harness never touches the developer DB or storage and forces fakes and blank keys in fake mode (workspace.py). Errors are redacted (runner.describe_error).
- Tests: markers slow, network, and container (Docker test image; AADHI_EXPECT_FFMPEG=5.1). Fakes keep everything offline; a batch that adds a provider adds its fake (design 10.2 gate 4).
- Classic invariance: goldens plus the differential pixel test; a classic change needs the classic-change label (OPERATIONS.md:79-88).
- The Determinism suite (1x300, 3x100, reverse) runs in Docker from B1.
- Docker: non-root uid 1000 aadhi, tini as PID 1, allow-list COPY. Chromium keeps its sandbox via the seccomp profile, never unconfined or SYS_ADMIN (OPERATIONS.md:458-464).
- Python 3.11, ruff over aadhi tests scripts evals docker (ci.yml:61). Frontend: vendored libraries only, CSP script-src 'self', pinned versions with SRI in web/vendor/manifest.json via scripts/vendor.mjs.
- The design says new libraries need licence verdicts (§7.13).

## bugs_or_risks
1) HIGH: the documented B1 benchmark command cannot run in the app image. OPERATIONS.md:504-509 and scripts/bench_motion.py:28-29 say `docker compose --profile motion run --rm --no-deps render-worker-motion python scripts/bench_motion.py ...`. render-worker-motion uses target app (docker-compose.yml:34-38, 151-153). The Dockerfile copies only aadhi/, alembic/, server.py, web/, docker/app/ and branding (Dockerfile:76-87), and tests/evals/test_tooling.py:364 asserts no runtime COPY source starts with scripts or tests. So /app/scripts/bench_motion.py does not exist. Even if it were mounted, it reads tests/core/fixtures/showcase_ohms_law.json (bench_motion.py:61) and the stub stage under tests/compose/motion/stub_stage (62), both excluded by .dockerignore ('tests'). This blocks the one remaining B1 acceptance item. A fix needs a bind mount of the checkout (e.g. -v "$PWD:/src" -w /src, plus --web-dir /app/web or a host `npm ci` for web/vendor), use of the test target, or shipping a fixture with the script.
2) HIGH (correctness, B4-facing): presentation.captions_burn can never take effect through the API. caption_modes uses the presentation only when payload['burn_captions'] is None (aadhi/compose/motion/job.py:58-68). RenderBody.burn_captions is a bool defaulting to False, and job_options() always writes it (aadhi/api/routers/renders.py:50, 57). The Studio always sends it from an unchecked checkbox (web/js/studio/views/editor/editor.js:1584, 1624; projectDetail.js:278, 302). Result: a Dynamic lecture whose presentation says captions_burn=True (the schema default, aadhi/schemas/screenplay.py:799; design's default destination is burned) renders clean via the Studio or API, and Render.options records burn_captions=false. Only the unit test feeds an empty payload (tests/compose/motion/test_job.py:46). INTERFACES.md:376 documents the unreachable behaviour.
3) MEDIUM: eval fake mode is weaker than the test suite's forcing. aadhi/evals/workspace.py:31-47 sets LLM/TTS/IMAGE/VIDEO_PROVIDER=fake and blanks keys, but not VIDEO_PROVIDERS, IMAGE_FALLBACK_PROVIDERS, VIDEO_FALLBACK_PROVIDERS, DYNAMIC_FEATURES or ALLOW_FAKE_PROVIDERS. tests/conftest.py:41-46 blanks them, explicitly because 'a developer .env must not switch the fake off'. With VIDEO_PROVIDERS=veo,omni in .env, `aadhi.evals run --provider fake --assets` gets no fake clips (veo and omni are unconfigured, so no spend, but results differ). Pollinations (keyless) as an image fallback could reach the network if the fake image provider ever failed. scripts/dev_demo.py:23-46 and render_parity.configure_env (128-142) have the same gap. B3 adds providers and keys (Azure, Lyria, ElevenLabs music) that each of these forcing lists must also blank.
4) MEDIUM: there is no automated guard on the motion compose service (see gaps). A future edit dropping its security_opt would break Chromium's sandbox, or tempt someone to use unconfined, unnoticed.
5) MEDIUM: evals/render_parity.py dynamic_timeline() (550-593) is a hand-built Dynamic timeline. It hard-codes presentation fields (fonts display/body/mono, personality 'crisp', caption styles), looks (template board_generic, mesh_drift/colour_block, transition kinds) and stand-in kinetic chunks (501-531). It is the shared fixture of about 15 test modules via tests/compose/dynamic/helpers.py:43-44, including the determinism suite. B2 schema or catalogue changes (themes.json, kinetic.py, new templates) must keep it valid, and its stand-ins can mask divergence from the real direct.py/kinetic.py output.
6) LOW: metrics.estimate_minutes and estimate_scene_seconds (metrics.py:322-338) count hidden scenes and ignore min_seconds/hold, unlike lint's lecture.duration_mismatch. This only skews screenplay fixtures that use those fields.
7) LOW: Manim assumes the classic dark purple look. The QA prompt says 'dark purple background' (aadhi/manim/prompts/qa.md:2), ManimRenderRequest.background defaults to '#1A0B2E' (base.py:36; config manim_background config.py:283), and named colours are fixed (aadhi_scene.py:34-45; templates/_base.py:23). Light families (e.g. paper_ink, render_parity.py:537) need asset_style bg and role-mapped colours (design 727, 945) or the vision QA will misjudge.
8) LOW/ops: `docker compose --profile motion up -d` without `--scale render-worker=0` runs both render workers on one host. Slots prevent CPU oversubscription across motion renders, but classic renders in render-worker do not take slots. This is documented (OPERATIONS.md:490-496), but it is an easy mistake.
9) RISK: the CI container job (ffmpeg 5.1 checks, determinism, differential) has never run (design 2425, 2517). Its first run may surface ffmpeg 5.1 differences. The Pillow WOFF2 support in the Debian image that B2 depends on is unverified (design 878, Appendix D #13).
