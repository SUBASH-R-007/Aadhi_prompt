# schemas-core: aadhi/schemas/** (screenplay, timeline, manifest, features, generate, jsonsafe), assets_auth, models, config, credentials, db, stage, changes, library, review, scratch, dev_schema, main, worker, cli, logging_setup, alembic/** (0001-0006), web/schemas/*.schema.json


## summary
This slice holds the data contracts and core plumbing of Aadhi EduEngine v2. aadhi/schemas/screenplay.py is the central content contract (scenes, beats, board items, side panels, companion sheet). aadhi/schemas/manifest.py records what the asset stage produced (audio and media per scene). aadhi/schemas/timeline.py is the fully timed document that both the live player and the MP4 renderers read. The B0 "schema v3" work is complete here. Every Dynamic-video field from design §6.7/§8.2 exists as an inert pydantic field with an exclude_if default: Presentation, SceneLook, PresenterSpec, VoiceCast, MusicChoice, HookRef, the five new BoardItem kinds, cuts, overlays, ClipScene, ResolvedLook, VisualEvent, KineticChunk, MusicPlan, SfxCue, TimedOverlay, MusicAsset and the new BeatAudio/SceneAudio/MediaInfo fields. Each is declared in per-model V3_FIELDS/V3_VALUES/V3_MODEL maps, and aadhi/schemas/features.py walks those maps to (a) find the features a document uses, (b) stamp schema_version=3 on any document that uses one (2 otherwise), and (c) refuse documents newer than READER_SCHEMA_VERSION=3 with NewerDocumentError. NewerDocumentError deliberately does not subclass ValueError. Write gates use Settings.dynamic_features (config.py:366), which is empty by default, through api/screenplay_service.require_features. aadhi/assets_auth.FIELD_RULES lists the 9 key-bearing fields with the asset kinds and MIME families each may hold, including the 4 Dynamic ones; record_asset_refs is the single AssetRef inserter. The web/schemas/*.schema.json files are generated by `python -m aadhi.schemas.generate`, and `--check` passes now (exit 0). models.py defines 14 ORM tables. Alembic runs linearly 0001→0002→0003_asset_claims→0004_claim_operation→0005_library_items→0006_visual_reviews (head), and neither B0 nor B1 needed a migration. config.py already has the B1 motion-engine settings (DYNAMIC_ENABLED, RENDER_MOTION_WORKERS, RENDER_CPU_SLOTS, RENDER_SLOT_DIR, MOTION_X264_PRESET/CRF) and H0 (gemini_tts_model = gemini-3.8-flash-tts). It has no B2 settings (DYNAMIC_AADHI_INTRO) and no B3 settings (Azure, music/Lyria, ElevenLabs v4). credentials.py covers only the gemini/openai/anthropic key providers, and it will crash at import if CREDENTIAL_PROVIDERS is extended without changes (see risks). changes.py (generated snapshot, diff and revert), review.py (Visual Review), library.py (per-user media library and matcher) and stage.py (lesson stage derivation) are classic features, mostly unaware of Dynamic. Of the v3 timeline/manifest models, only TimelinePresentation and ResolvedLook have a producer so far (aadhi/compose/presentation.py, B1, outside this slice). VisualEvent, KineticChunk, MusicPlan, SfxCue, TimedOverlay, MusicAsset, BeatAudio.persona/words_exact and SceneAudio.lufs/speaker_gains are defined but never constructed anywhere in aadhi/ (grep). main.py is the FastAPI factory (middlewares, 21 routers, lifespan doing create_all on dev SQLite or the Alembic-head check elsewhere). worker.py and cli.py are the operator entry points.

## conventions
- Every schema model subclasses StrictModel: extra='ignore', populate_by_name, str_strip_whitespace, allow_inf_nan=False (screenplay.py:182-196).
- A new field on an existing (v2) model must be: (1) declared in that class's V3_FIELDS (or V3_VALUES for an enum value) mapped to one of the 6 DYNAMIC_FEATURES; (2) given exclude_if that drops its default (patterns: `exclude_if=lambda v: v is None`, `lambda v: not v`, `lambda v: v is False`, `lambda v: v == 0`); (3) documented with a `# v3` comment. A wholly new model is either v3-only (add it to V3_ONLY_MODELS in tests/schemas/test_v3_schema.py:47-52) or carries V3_MODEL. After any schema change, run `python -m aadhi.schemas.generate`, update web/js/shared/types.js by hand, and regenerate the maximal fixture.
- Subclasses extend inherited V3 maps explicitly: BoardScene.V3_FIELDS = {**SceneBase.V3_FIELDS, ...} (screenplay.py:899).
- Ids use reusable normaliser validators: `_norm_id = field_validator('id', mode='before')(_slug_validator)`, `_opt_slug`, `_slug_list`, `_item_ref`. Validators raise ValueError with messages prefixed "scene {id}: ..." (screenplay.py:874-936).
- Free-form dict/Any fields are checked with check_storable (screenplay.py:589-594, timeline.py:188-219, manifest.py:118-122).
- Documents are read with validate_stored (models.py:198-224) and replaced whole, never mutated in place (models.py:3-5, db.py:6).
- DB state changes are single atomic statements (compare_and_set / atomic_add / ON CONFLICT upserts) that execute but never commit; the caller commits (assets_auth.py:83-86, review.py:379-395, credentials.py:225-264).
- Batched IN lists of 500 keys to stay under SQLite's bind limit (assets_auth.py:98, review.py:422, 469, 508).
- Migrations: revision id 'NNNN_slug', idempotent (`_existing()` / `_tables()` inspect checks, offline-safe via context.is_offline_mode()), batch_alter_table for SQLite, constraint names from NAMING_CONVENTION via op.f (0002-0006). New columns should be nullable or have server_default so dev SQLite gets them through dev_schema.add_missing_columns (dev_schema.py:29-31).
- Settings: one field per env var, with an inline trailing comment explaining it in plain words, grouped under `# --- Section ---` headers that name the code paths. Lists use Annotated[list[str], NoDecode] plus a _split validator. Secrets are SecretStr (all are auto-collected by secret_values for redaction).
- Determinism: SHA-256 seeds, never Python hash() (compose/presentation.py:9). Content-addressed asset keys (storage/assets.bytes_key).
- Docstrings cite design sections (e.g. '§6.7', 'R-01', '[RV E-3]') and explain *why*. User-facing messages are plain sentences (e.g. changes.py:270, review.py:198-206).
- Lines are wrapped at about 120 characters; `from __future__ import annotations` everywhere; `__all__` declared in shared modules.
- Tests stay offline with fakes; schema invariance is tested generically (tests/schemas/test_v3_schema.py).
