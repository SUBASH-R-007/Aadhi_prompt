# tests-web: web/tests/** (dynamic/, motion/, panels/, player/, render/, studio/, ui_tokens/), package.json, tsconfig.json, scripts/vendor.mjs, web/vendor/manifest.json


## summary
The frontend test suite is ~24.5k lines in 101 files under web/tests, run by `npm test` = `node --test "web/tests/**/*.test.{js,mjs}"` (package.json:8) on Node 22 (local v22.17.1; CI .github/workflows/ci.yml:73-92 runs `npm ci` (which runs scripts/vendor.mjs), then `npm run typecheck`, then `npm test`, with no Python venv). There is no bundler and no test framework beyond node:test, node:assert/strict and jsdom 24.1.3. TypeScript 5.9.3 is used for `tsc` typecheck and, as a library, by the determinism source scan. The Dynamic-mode tests sit in web/tests/dynamic (9 test files plus _fixture.js, about 2.3k lines) and the motion toolkit tests in web/tests/motion (8 files, about 1.0k lines). Together they cover the B1 JS deliverables: the motion toolkit and its module contract; frame maths and keys (core.js); roles and zones; captions; the timer guard; the mesh_drift and colour_block backgrounds; cut and crossfade; media frame planning and chunk-split continuity; board_generic layout and text entries; the stage (purity in any seek order, crossfade, cards, quiz, caption-only layer, textBoxes, preflight remedies, font-face waits); the render page / window.aadhiStage v3 boot contract; the live player's handling of Dynamic timelines; and the static determinism source scan (TypeScript AST scan of web/js/dynamic/** and web/js/motion/** plus CSS/HTML scans). I ran only sourceScan.test.js, read-only: 22/22 pass on the current tree. The other folders test the classic product and Studio: player/ (classic live and render player, mascot, schedule, sync cues, audio plumbing), panels/ (side panels, graph maths parity with screenplay.py, skill tree), render/ (classic render page, fonts, p5 sandbox), studio/ (Studio SPA views, editor, B0 transform-survival and batch-4 regressions, API keys, options form) and ui_tokens/ (WCAG contrast and the 12 px type floor for Studio CSS). Several assertions are deliberately pinned to the B1 state and will need deliberate updates in B2: only board_generic in TEMPLATES, only two backgrounds, Poppins falling back to Outfit, and exactly 10 base font faces. The suite depends on per-file process isolation, because jsdom globals are installed at import time and never restored. web/vendor is generated by scripts/vendor.mjs on postinstall and is gitignored (.gitignore:32). Its manifest.json is a flat map of vendor-relative .js paths to sha384 SRI strings (52 entries), and the invariance tests use it as a presence check.

## contracts
Frozen B1 JS contracts that the tests pin. Change any of these only deliberately.

**Stage API v3 (window.aadhiStage)**
- `STAGE_VERSION = 3` (web/js/dynamic/render.js:31; dynamic/render.test.js:63, :178).
- `installStageApi(w)` defines `w.aadhiStage` at once; `info()` and `seek()` throw or reject /not ready/ until boot finishes (render.test.js:176-184).
- API members:
  - `ready`: Promise of `{webgl:boolean}`
  - `error`: null or `{code, message}`
  - `info()` → `{width, height, fps, frames, scenes:[{index, f0, f1}]}`
  - `seek(frame:int)` → Promise of `{key: 16-hex}`; RangeError for a negative, fractional or ≥ frames value, and the queue keeps working (stage.test.js:194-207)
  - `textBoxes()` → `[{x, y, w, h, role, critical, ink, bg, overflow, alpha, scene, slot, size, min, weight, text}]`
  - `mediaPlan(f0, f1)`
  - `setLayers({stage?, captions?})` → `{stage, captions}`
  - `layers()`
- Boot error codes: `token_missing`, `timeline_http` (message contains 'HTTP <status>'), `timeline_invalid` (a classic timeline), `fonts_missing` (render.test.js:113-141).
- A seek whose /__frames/ image is missing rejects with /media frame failed to load: \/__frames\// (render.test.js:100).
- Token handling: the token is read from the URL fragment `#token=` and the fragment is then cleared. GET goes to TIMELINE_ENDPOINT '/api/render/timeline' with `Authorization: Bearer` and `credentials:'omit'`.
- Page sizing: `documentElement.lang` = board_language; CSS var `--render-stage-width` is set from the timeline.

**Frame maths and keys** (core.js)
- `frameOf(t, fps) = floor(t*fps + 0.5)`.
- `DEFAULT_FPS = 30` (core.js:22); a non-integer or zero fps falls back to 30.
- Scene ranges are contiguous and each scene owns at least 1 frame.
- `Hasher` digest: 16 hex. `Painter.begin/style/note/digest` hashes every write but skips unchanged DOM writes.
- `fx(n, d=3)` never returns '-0.000'.

**Media frames** (media.js)
- `FRAMES_PREFIX '/__frames/'` (:29); `frameUrl(key, n) = /__frames/<key>/<6-digit n>.jpg`.
- `mediaKey(kind, asset, [w,h])` = `v-<16hex>-WxH` for video, prefix `a-` for the Aadhi presenter.
- `LIVE_DRIFT 0.1` (:47); `LOOKAHEAD 10` (:49).
- `sourceFrame = floor((t + trim_in) * srcFps + 1e-6)`, wrapped for loop, held at the last frame for freeze/clamp.
- `mediaPlan(tl, f0, f1, boxFor)` → `[{kind, key, asset_key, srcFps, frames:int[], size:[w,h]}]`; the size never depends on the chunk.
- `shownIn(ref, 'render')` is false for `render_in_mp4:false` or a missing asset_key.

## conventions
**Runner and assertions**
- Use `node:test` (`test`, `describe`, `before`/`after`/`afterEach`, `t.after`, `t.mock.timers`, `t.diagnostic`, `t.skip`) with `node:assert/strict`.
- No snapshot files. Exact values are pinned inline, including vectors cross-checked with Python.
- Files start with `// @ts-check` and use JSDoc casts `/** @type {any} */ (x)`. These are not typechecked: tsconfig includes only web/js.
- Test names are full sentences stating the behaviour.
- The assertion message argument explains the intent ('a rejected seek does not block the queue').
- Comments cite design sections (§7.3, R-59, …).

**DOM setup**
- Import `installDom`/`uninstallDom` from `../player/_dom.js`.
- Pure-module tests (motion, transitions, state) import nothing from the DOM.
- Stage-module tests import statically and call `installDom` in `before()`. The stage modules do not touch the DOM at import time.
- Player tests call `installDom()` before `await import('../../js/player/player.js')`.
- Studio tests import './_dom.js' first; it installs jsdom at module load.
- Globals are never restored between files. The suite relies on node --test running each file in its own process.

**jsdom limits and how tests work around them**
- No canvas: backgrounds fall back to DOM, `grainTile` returns ''.
- No layout: stub `window.HTMLElement.prototype.getBoundingClientRect` and restore it in `t.after`.
- No FontFaceSet: define `document.fonts` with load/ready/status/addEventListener.
- `HTMLImageElement.prototype.decode` is patched.
- Media playback is faked by patchMedia.
- No AudioContext: SpeechMeter degrades.

**Dependency injection instead of real timers or network**
- Stage: `{texIdle: () => Promise.resolve(), frame: () => Promise.resolve()}` (the `fast` object, stage.test.js:15).
- Player: `deps {now, requestFrame, cancelFrame, waitForFonts:false, createDynamicStage, renderTex, createPanel}`.
- Render boot: `{window, fetch, loadMathJax, texIdle, frame, renderTex}`.
- Studio: `mockFetch` routes, `FakeEventSource`, `fakeApp`.

**Determinism rules for any code under web/js/dynamic and web/js/motion** (enforced by sourceScan.test.js)
- No `Date.now`, `performance.now`, `new Date()`, `Date()` or `document.timeline`.
- No `Math.random`, `crypto.getRandomValues` or `crypto.randomUUID`; use `motion/random.js` `seededRandom(seed, scene_id, purpose)`.
- No timers, `requestAnimationFrame`, WAAPI `.animate([...])`, CSS transition/animation/@keyframes or smooth scroll. Writing `style.transition = 'none'` is allowed.
- Chart.js must get a literal `animation: false` or `Chart.defaults.animation = false`.
- No self-clocked libraries (GSAP, tsParticles, Lottie, anime, motion, …).
- No `<video>` without a reasoned pragma.
- web/js/motion must not touch DOM or host globals.
- Templates must not apply struct.* roles to content nouns: item, node, row, bar, tile, symbol, caption.
- Templates must not use mark/focus roles, outline or text-decoration. Emphasis belongs in cues.js only.
- Every visual write goes through `ctx.paint` (Painter) so the frame key covers it.

**How a new B2 template module test should look**
Put it at web/tests/dynamic/<id>.test.js, or under a subdirectory (the package.json glob covers it; adjust the relative imports). The pattern is:

```js
// @ts-check
import { test, before, after } from 'node:test';
import assert from 'node:assert/strict';
import { installDom, uninstallDom } from '../player/_dom.js';
import tpl, { /* pure helpers */ } from '../../js/dynamic/templates/<id>.js';
import { Painter, makeRoles, ZONES, insideAny } from '../../js/dynamic/core.js';
import { createDynamicStage } from '../../js/dynamic/stage.js';
import { dynamicTimeline } from './_fixture.js';

before(() => installDom());
after(() => uninstallDom());
```

1. **Pure parts first:** variants, specs, layout regions inside `ZONES[format].critical` and above `zones.caption.y0` for both formats.
2. **Direct ctx test**, built like stage.test.js:331-339:

   ```js

     scene, index, timeline: tl, look: scene.look,
     roles: makeRoles(tl.presentation, scene.look),
   ```

   Then: `ctx.view = tpl.build(ctx); tpl.layout(ctx); tpl.update(ctx, t, {terminalLines: [], countdownRemaining: null}); tpl.texts(ctx)`. Assert roles, critical, slot, size, min and weight against R-29 floors (BODY_WEIGHT, MIN_LABEL, MIN_TEXT).
3. **Stage-level test:** set `scene.look.template = '<id>'` on a fixture scene, then `createDynamicStage(root, tl, {mode:'render', texIdle, frame})`.
4. **Purity across seek orders**, fresh vs reverse vs repeat (copy stage.test.js:209-227).
5. **textBoxes** with a stubbed getBoundingClientRect (copy stage.test.js:449-488).
6. **Contrast** via `contrastRatio` for every family (copy stage.test.js:304-322).

8. **Source scan:** the module is picked up automatically because it lives under web/js/dynamic/templates.

## bugs_or_risks
1. **Hidden dependence on per-file process isolation.**
   - dynamic/render.test.js:13-33 sets window/document/Node/… on globalThis and never restores them.
   - Player and dynamic tests call `installDom()` at import time; studio/_dom.js installs jsdom at module load.
   - motion/index.test.js:7-12 asserts `globalThis.window === undefined`.
   - Running `node --test --test-isolation=none` (Node ≥22.8) would make index.test.js fail and could leak state between files. CI uses the default isolation, so this is latent.

2. **B1-pinned assertions will fail as soon as B2 lands.** These need intentional updates, not weakening:
   - stage.test.js:38 `Object.keys(TEMPLATES)` deepEqual ['board_generic']
   - stage.test.js:39 BACKGROUNDS keys
   - stage.test.js:37 formula_focus fallback
   - stage.test.js:106 the Poppins→Outfit assertion
   - render/fonts.test.js:12 and :45: exactly 10 base faces
   - render/fonts.test.js:64: the 'Outfit 300/400/700/900' missing list
   - dynamic/render.test.js:143-151: the family set

3. **Source-scan blind spots** (sourceScan.test.js):
   - (a) struct-role and emphasis checks need a string literal at the call site (l.311, l.355), so `roles.color(MARK)` with a constant evades them.
   - (b) The timer rule checks only call names (l.284), so `const t = setTimeout; t(f)` evades it. The runtime guard covers only setTimeout and setInterval, and only after ready (guard.js:15); setImmediate, requestIdleCallback and queueMicrotask are unguarded at runtime.
   - (c) Only web/js/dynamic, web/js/motion, web/css/dynamic.css and web/render-dynamic.html are scanned (l.19-21). New B2 assets under web/dynamic/ (themes.json, gallery.html) or extra CSS files would not be scanned unless the lists are extended.

4. **Fragile allow-list test.** captions_guard_backgrounds.test.js:83 depends on its own file name appearing in the stack trace, so renaming the file breaks it.

5. **Possible live/MP4 audio parity gap that no test covers.**
   - For Dynamic timelines the live Player still builds `SoundEffects(branding.tick_url, ding_url)` and `BackgroundMusic(branding.bgm_url)` (player.js:333-335).
   - It ducks by the classic schedule phase (player.js:729).
   - So any branding BGM on a Dynamic timeline would play live with classic ducking, while the MP4 audio comes from the Python mix.
   - dynamic/player.test.js does not assert the absence or presence of audio.

6. **Parity tests built on the graphMath pattern would skip in CI.** That test (graphMath.test.js:127-163) runs Python through .venv, and the CI web job has no venv. A B2 'Python/JS catalogue parity' test must therefore live in the Python job, or read a shared JSON (themes.json) from both sides.

7. **vendor.mjs fragility.**
   - It deletes web/vendor entirely on every run (l.13).
   - Its subset filter (l.67) would silently drop subsets of new families (e.g. Anek per-script packages, Bengali).
   - The manifest hashes JS only, so tampered fonts or CSS are not detectable through it.

8. **The fixture under-represents R1 content.** No v3 items, no events and one template mean that new template code paths (cues, item kinds) start with no regression net until _fixture.js is extended.
