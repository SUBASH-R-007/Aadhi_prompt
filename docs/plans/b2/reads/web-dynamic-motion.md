# web-dynamic-motion: web/js/dynamic/** (core, stage, render, guard, state, captions, media, transitions, backgrounds/**, templates/**), web/js/motion/** (easing, track, color, text, draw, random, count, index), web/css/dynamic.css, web/render-dynamic.html, and how web/js/player/player.js mounts the dynamic stage


## summary
This slice is the B1 "motion engine" front end: one compositor (web/js/dynamic/stage.js createDynamicStage) that both the live player (mode 'live') and the MP4 render page (mode 'render', /render-dynamic) use, so the MP4 and the preview are drawn by the same code. Each frame is a pure function of (timeline, t). The scene that owns the frame is painted by its template at scene time over its background (the background runs on a clock that is frozen during holds). During a crossfade, the previous scene's final state is painted underneath. The in-stage caption layer is painted last. Every time-dependent DOM write goes through core.js Painter, which skips writes that change nothing and hashes every (key, value) call into a 16-hex frame key (stage.js:431-454, core.js:127-213). The render page (render.js) installs window.aadhiStage v3 {version, ready, info, mediaPlan, seek, textBoxes, setLayers}. Before resolving `ready` it loads the timeline with the fragment token, preloads every font face, pre-converts all TeX, and paints frame 0 without media frames. After `ready`, guard.js makes setTimeout and setInterval throw. Python's stage_page.py consumes exactly this contract (STAGE_VERSION 3, /__frames/ prefix, 'timer guard' log matching). Only one template exists: board_generic. It renders stacked cards (at most 3 visible, 2 in 9:16), a "+n earlier" chip, title/media/split/stack variants, quiz option cards with a countdown ring, chapter cards as centred titles, misconception myth/fact cards, tables, figures, terminal cards and formula legend rows. It has two backgrounds, mesh_drift (a 1/8-scale canvas stepped every 0.2 s) and colour_block (an accent block with a seeded grain tile), and two transitions, cut and crossfade. Captions are phrase captions or kinetic_captions in one fixed band per format, styled clean_pill or bold_outline. A caption-only layer mode (setLayers {stage:false}) exists for the burned second version. web/js/motion is a pure toolkit with no DOM access and no clock: a CSS-exact cubic-bezier solver and motion tokens, keyframe tracks, OKLCH colour maths with CSS Color 4 gamut mapping and WCAG contrast, Intl.Segmenter grapheme and word splitting with Indic conjunct joining, stroke dashes, a seeded mulberry32 RNG with hashSeed (FNV-1a plus fmix32), and count-ups. Most of the toolkit is not used yet (track, splitLines, countUp, pop and stagger wait for B2). The live player (player/player.js) detects presentation.style === 'dynamic' (player.js:97, 315). For such a timeline it skips the mascot and classic captions, sizes the logical stage from timeline.width/height (a reel is 1080x1920), lazily imports dynamic/stage.js, and calls stage.update(t, {playing, rate, seeked}) on every clock tick. Narration remains the master clock. Render mode of the player stays classic. The code matches the B1 scope and the B1 'as built' notes in the design doc. B2 hooks are wired but receive no data yet: look.presenter, reveal/fill events, kinetic_captions, the preflight remedies (variant 'safe', text_fit size/scrim) and focusRect. Nothing from B3 exists in the stage. web/js/dynamic depends on player/schedule.js (sceneIndexAt, planScene, sceneStateAt, selectCue), player/richtext.js, player/icons.js, player/kenburns.js, render/fonts.js, render/render.js, shared/dom.js and shared/libs.js. Changes to any of these files affect MP4 output.

## conventions
Every file starts with `// @ts-check` and a header docblock that names the DYNAMIC_VIDEO_DESIGN section and rule ids (R-xx) it implements. Types are JSDoc typedefs, imported as `import('../shared/types.js').X`. tsc typecheck is the `npm run typecheck` gate.
Determinism (enforced by web/tests/dynamic/sourceScan.test.js):
- No Date.now, performance.now, new Date(), Math.random or crypto random in web/js/dynamic/** or web/js/motion/**.
- No timers, requestAnimationFrame, CSS transition/animation/@keyframes, WAAPI or self-clocked libraries.
- No <video> except in live-only code with a reasoned pragma on the same line or the line above, e.g. `// determinism-allow video: <reason>` (media.js:312, stage.js:217) or `// determinism-allow raf: ...` (render.js:149). Pragmas are never allowed in motion/** or templates/**.
- web/js/motion has no DOM or host globals.
Painting:
- Every time-dependent DOM write goes through ctx.paint (Painter.style/attr/text). Inputs that are not DOM writes use paint.note.
- CSS numbers are rounded with fx().
- Positions are whole-pixel translate3d. Pictures and text are never scaled. There is no will-change (measured: order-dependent frames otherwise; dynamic.css:6-7, board_generic.js:884-886, 931-933).
- Seeded randomness only: hashSeed/mulberry32 or ctx.rng.
- `build` creates DOM without measuring. `layout` measures, is idempotent, and resets from build-time values (board_generic.js:695-700) because it re-runs on font loads. `update` is a pure function of (t, state).
Colours and emphasis:
- Colours only from ctx.roles.color(role) or ctx.onBackground.
- struct.* roles only on structure. The scan fails a statement that names item/node/row/bar/tile/symbol/caption without a structure noun.
- mark/focus roles, outline and text-decoration are banned in templates; they belong to the future cues.js.
DOM and text:
- Build DOM with h()/svg() from shared/dom.js (text nodes only, numeric styles become px).
- Rich text via renderRich/mountTex with {pending: ctx.pending, renderTex: ctx.renderTex} so render mode awaits TeX.
- Pictures via ctx.media() so render mode awaits their decode.
- UI strings sit in an exported LABELS table.
- Constants are exported in UPPER_CASE with a doc comment giving the rule and the measured reason.
Naming and errors:
- British spelling in identifiers and ids (colour_block, colour roles).
- Errors carry a `.code` string for the worker. Infrastructure never throws on optional features (canvas2d returns null under jsdom; DOM fallbacks exist).
Tests:
- node:test + node:assert/strict + jsdom via web/tests/player/_dom.js installDom/uninstallDom.
- Fixture dynamicTimeline(format) in web/tests/dynamic/_fixture.js.
- `fast` deps {texIdle, frame} resolve immediately.
- getBoundingClientRect is stubbed when testing textBoxes (stage.test.js:449-488).
- Run with `npm test` (`node --test web/tests/**/*.test.js`).
Comments explain why, often citing a measurement.

(9) R-54. colour_block's rule that scenes always cross-fade into and out of it is enforced only in Python (presentation.py:221-222), not by the stage.

## bugs_or_risks
1. BUG (confirmed): Dynamic quiz questions lose rich-lite markup.
- board_generic.js:487 sets titleText = String(quiz.question), and :502 splits it into plain word spans (wordSpans :464-473 uses `text:`).
- The classic quiz renders the question with renderRich (player/scenes/quiz.js:78). quiz.question is translatable rich-lite text.
- Result: a question like 'If $V = IR$ and **R** doubles...' shows literal `$`, `**`, `[[ ]]` and backticks in the MP4 and the live player.
- render.js:57 even pre-converts the question's TeX, which is then never used.
2. BUG (confirmed): the scrim remedy is never reported as fixed, and non-title slots ignore it.
- board_generic.texts() reports `bg: ctx.onBackground.bg` (the worst background colour, :978, used at :984-995) even when the title block has a scrim (:507-511, background `${tokens.bg}c7`).
- So preflight's second pass computes the same failing ratio. _finalise (preflight.py ~589-616) then escalates the contrast finding to 'warn' instead of 'fixed', and the teacher-facing report keeps the warning.
- Only text_fit.title.scrim is honoured (:507). A scrim remedy planned for slot 'kicker' (a critical kicker on chapter cards, :984) is ignored.
3. RISK (determinism): Ken Burns pictures are scaled.
- MediaView paints `translate(%) scale(s)` on an <img> every frame (media.js:348-352, kenburns.js:41-42).
- This contradicts the B1 measurement that scaling pictures make frames depend on previously painted frames, because of Chromium's decoded-image cache (board_generic.js:884-886; design B1 deviations: 'rising (never scaling) pictures').
- Python attaches ken_burns to AI-video fallback stills (aadhi/compose/timeline.py:452-459). The determinism fixture has no Ken Burns image, so this path is untested for 1x300 / 3x100 / reverse equality.
4. LIKELY BUG (live, 9:16): showing the control bar pushes reel captions into the cards.
- controls.captionLift assumes classic captions 40 px above the stage bottom (controls.js:23, 35-39).
- dynamic.css:750-752 applies the same --caption-lift to the 9:16 band at y 1040-1240 (core.js:380), which is about 680 px above the bottom and needs no lift.
- The lift moves the captions up toward or over the card column, which ends at y 1020 (core.js:383).
- Needs a visual check on a phone-sized player.
5. LIKELY BUG (16:9 quiz): the countdown ring can overlap the question.
- The ring is placed at x 1728-1824, y 50-146 (board_generic.js:676-678).
- The quiz title block spans x 96-1824 from y 54 (layout :613-621), and the quiz header is forced chipless (full width, :682 and :846), so a long first line of the question (or a long kicker) can run under the ring during the countdown.
- The ring is not in textBoxes, so preflight cannot see the overlap.
6. RISK (B2 integration): media keys can mismatch the plan.
- stage.mediaPlan sizes clips with board_generic.mediaBoxMax only. Any other template gets the full stage (stage.js:529-532).
- A new template that passes a different box to ctx.media() gets a different media key (media.js:305 vs 191), so the page requests /__frames/ files the worker never extracted. The seek then rejects with 'media_frame' and the render fails.
7. RISK (dormant until B2): presenter clip has two problems.
- The live presenter clip never sets playbackRate (stage.js:121-135; compare media.js:389), so at rate != 1 it drifts and is re-sought every >0.1 s and stutters.
- Live presenter requires `p.url` (stage.js:216), but Python's presenter dict has no url (schemas/timeline.py:216), so it would never show live.
8. RISK: TeX cache eviction.
- texNode's cache holds 400 entries and evicts the oldest (richtext.js:279-298).
- A lecture with more than 400 distinct TeX strings evicts pre-converted entries, so slots built during capture call MathJax after `ready` (render.js:171-176 assumes no MathJax work while capturing). The seek still awaits texIdle, but any MathJax timer would trip the guard.
9. RISK (parity): live-only CSS reaches stage elements.
- .ap-icon (player.css:1023: inline-block, vertical-align middle) and base.css MathJax rules (base.css:160-210) apply to stage elements only on live pages. render-dynamic.html loads only tokens.css and dynamic.css (:9-10).
- Harmless today because every stage icon is a flex or grid item. An inline icon or new MathJax usage in a B2 template would render differently in the live player and the MP4.
10. COSMETIC (light families paper_ink and mint_studio, presentation.py:143-147): literal colours in dynamic.css.
- The ring track rgba(255,255,255,.18) (dynamic.css:714) is nearly invisible on bg L≈0.965.
- The letterbox colour #0b0d14 (:654) puts dark bars around contained media.
11. MINOR: frame key and layout.
- The frame key excludes layout results (title font size, card schedule) because layout writes styles directly (board_generic.js:614-693).
- Keys stay valid within a seek (which re-lays out after font loads, stage.js:506-513), but B9 static-run deduplication must not compare keys across a re-layout.
12. MINOR: stage errors flood. player.js:723-727 reports a stage update exception on every frame, flooding 'error' events.
13. MINOR (docs): templates/types.js:40 lists TextEntry roles without 'subtitle', which texts() emits (board_generic.js:994; INTERFACES.md lists it).
14. MINOR: Python and JS gamut mapping differ.
- Python oklch_hex lowers chroma until the colour is in gamut (presentation.py:104-116). JS uses the CSS Color 4 MINDE algorithm (color.js:97-129).
- Today Python emits only in-gamut hex, but B2 validators that predict JS-mixed colours (blockColors, blockInk2, derived surface, mesh tints) must use the JS algorithm.

## b2_b3_touchpoints
B2 (visual system):
- Template registry: stage.js:42 TEMPLATES and :60 templateFor. Each new module is web/js/dynamic/templates/<id>.js with default {id, build, layout?, update, focusRect?, texts?}. Context fields are listed at stage.js:176-185; add `cues` there, and type it in templates/types.js:12-35.
- What a new template must do:
  - build: create DOM under ctx.root without measuring. Push TeX and pictures to ctx.pending through renderRich/mountTex and ctx.media(ref,{box,start,alt}).
  - layout: idempotent and re-runnable (fonts). Reset any state derived from build.
  - update(ctx,t,state): write only through ctx.paint; call MediaView.update(p,t,ctx.frameInfo||{}) every frame, even while hidden (board_generic.js:887-888); honour ctx.reducedMotion.
  - texts(ctx): honest bg (including scrims), alpha, slot, size, min, weight and overflow in px (vertical and sideways).
  - Honour look.variant 'safe' and text_fit[slot] {size, scrim} (reuse slotTuning, board_generic.js:1018).
  - Colours only via roles. Structure roles only on structure. No mark/focus/outline/text-decoration outside cues.js (sourceScan.test.js:260, 293, 303, 311).
  - Add its CSS to dynamic.css with no transitions or animations.
