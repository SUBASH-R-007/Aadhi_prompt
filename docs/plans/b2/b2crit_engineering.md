## [critical] Determinism: transforms (scale, 3D, pop) used by the R1 choreography
PROBLEM: The plan considers scaling only for the morph ("no text scaling unless the determinism test proves it safe"). The R1 choreography needs scale or 3D transforms in many places. Camera push of 2-6% and punch-zoom 1.00 to 1.10 scale whole text layers. Icon and "?" pop overshoots to 1.08. Other cases: the 9:16 Aadhi card settles 0.96 to 1.0 (it shows video frames), media_split media goes 0.96 to 1, the myth card shrinks to 70%, recap tiles flip with rotateX 90 to 0, paper_grain breathes by 1% scale and spotlight by 3%. B1 measured that scaled pictures, inline SVG at fractional offsets and promoted layers make frames order-dependent. Only Ken Burns <img> scaling has since been measured safe, on Windows only. The plan also quietly redefines push as a translate (§1.4 "camera translate 2-6%"), yet keeps punch-zoom as "push at 10%". If any of these classes fails late, B2e/B2f templates have to be reworked.
EVIDENCE: Design §4.8 lines 960, 969; §4.3 lines 657, 681, 734; §3.3 line 535; §4.5 lines 851, 853; B1 deviations design:2505-2506; board_generic.js ~1055-1057 ('a rise, never a scale: Chromium's decoded-image cache...'), ~1102-1104 ('inline SVG ... differently at fractional offsets ... reverse renders differed'); dynamic.css:8-9 (promoted layer keeps the raster of its first scale); close_b1_docnotes G2 (4): Ken Burns measured order-independent on Windows only, container run pending; plan §1.4.
CHANGE: Add a spike to the start of B2a (no product code). Run it in the real-page 1x/3x/reverse harness (tests/determinism, Windows and the CI container job) on one fixture per transform class: (a) a scaled text layer at 0.9-1.1 (camera push/punch), (b) a scaled inline-SVG icon (pop), (c) rotateX on a card, (d) a scaled <img> of a /__frames JPEG (presenter settle, media 0.96 to 1), (e) a scaled background tile (paper_grain). ## [major] Fonts: classic invariance, Pillow measurement fidelity, preload
PROBLEM: There are four font gaps. (1) _copy_fonts copies every file in web/vendor/fonts into classic burn-in renders. New faces such as Anek, which covers Tamil and Devanagari, become libass candidates and could change classic burned captions; every classic render also copies MBs more. (2) The vendored faces are split by unicode-range (latin / latin-ext / script files), but Pillow measures with one file. textfit must therefore copy the CSS fallback chain per run (display face, then Inter, then the Indic families, by unicode-range), or it gets .notdef widths. Variable faces (Anek, Atkinson Next) measure the default instance unless the wght axis is set. (4) fonts.js BASE_FONTS and fontRequests list only Inter, Outfit and JetBrains Mono. If Poppins, Lexend or the new weights are not requested before ready, they load lazily mid-render.
EVIDENCE: video.py:556-564 _copy_fonts (iterdir of web/vendor/fonts, all font files); web/vendor/fonts/*-latin-*/-latin-ext-* subset files; stage.js:84-95 fontStacks fallback order; fonts.js:14-18 BASE_FONTS; render.js ~167-170 preloadFonts/fonts_missing; requirements.txt:42 pillow>=11.0,<13; design §4.6 lines 876-878.
CHANGE: Vendor the B2 faces into web/vendor/fonts/dynamic/. iterdir is non-recursive, so classic copies stay byte-identical; alternatively allow-list the families in _copy_fonts. ## [major] text_fit ownership and slot geometry
PROBLEM: Python's text_fit ({size, lines} from Pillow) and the page's own fitting both exist, and the plan does not say which one decides the pixels. If the page obeys Python's size and lines, differences between Pillow and Chromium become overflow and then preflight shrinks or blocks; Pillow BASIC ignores GPOS kerning and Indic shaping. If the page refits, `lines` is dead data. Slot geometry (box width, size range, line count, weight, face role) lives in JS LAYOUT tables while Python needs the same numbers. Type floors are already duplicated between preflight and board_generic, and the catalogue in §1.6 has no slots and no floors.
EVIDENCE: board_generic.js:78-84 MIN_FIT/MIN_TEXT/MIN_LABEL/BODY_WEIGHT and the title fitter (4 px steps); preflight.py:85-89 MIN_TEXT_PX/MIN_LABEL_PX/PORTRAIT_MIN_WEIGHT; plan §1.1 text_fit 'owned by the resolver', §1.6 catalogue contents; design §4.6 lines 875-877.
CHANGE: State that the page decides the pixels. text_fit.size is an upper bound the page starts from and never exceeds; `lines` is informative, for lints and the Studio. Python is biased conservative. Add `slots: {slot: {fmt: {w, sizes:(min,max), max_lines, weight, face_role, critical}}}` to TemplateSpec and export it, together with the R-29 floors, in the catalogue. JS templates and preflight read floors and slot geometry from it, so no literal floors remain. The slow test then becomes: Python fits ⇒ page overflow == 0 on every gallery slot, and Python overflow ⇒ page overflow > 0 or within the 4%/8% slack.

## ANSWERS
Q1 (generated JS module instead of web/dynamic/themes.json): Yes. A static ES module needs no fetch at boot, adds no new route or network-policy case, is typed by tsc, is scanned, and is covered by bundle_digest under web/js. Conditions: (a) generation is byte-deterministic, with `--check` in the Python CI job (the npm job has no venv, so the committed file is the snapshot); (b) at runtime it supplies only geometry, meaning zones, slot geometry and the R-29 floors, read through core.js. Palettes, durations and personality values are never read from it at runtime, so old timelines keep their look (§6.7). (c) Its exported shape is frozen as 'the themes.json schema' contract with a shape test, and the deviation is recorded.

Q2 (stage-driven vs template-driven cues): Stage-driven is better for R-26. It gives one budget, one drawing path and one place for the reduced-motion mapping. It needs the constraints in the cues finding: a per-Slot cue layer and a stage-owned camera wrapper; geometry through itemEl/focusRect, read after template.update and rounded to whole px; cues on the outgoing slot at its final time; the scan extended to Painter writes. Do not ship ctx.cues in B2. Two paths into the same limits invite double drawing, and no R1 template needs it: a formula's var tint is an entity-colour state, not a cue. Add it only when a template proves it needs it.

Q3 (build_timeline runs direct.py for missing/auto looks): This is consistent with §4.4/§6.8 ('auto' = re-chosen on the next run), with conditions:
- the result is never written back;
- presentation-level choices (family, personality, fonts, caption style) come only from the stored Presentation, and history is never read at build time;
- settled and pinned looks are kept unless their template's fit() is 0, in which case there is a deterministic re-pick that is not stored;
- the import is lazy inside the Dynamic gate, with a preview cost budget.
Expect global re-picks after edits until B4/B5 write settled looks. That is acceptable while the flag is off in production.

Q4 (kinetic_captions in 16:9 too): Yes. One caption source for the stage (captionAt) in both formats, plus per-chunk blank/key flags, is simpler than flagging Timeline.captions. Timeline.captions stays the classic split for sidecars, so classic bytes do not change. The 16:9 chunker has to reproduce 42×2 chars and ≥ 1.0 s (R-32) and measure with the caption face. Preflight samples chunk starts in both formats. This is a deliberate visible change for B1 16:9 Dynamic output, so regenerate the parity fixture.

Q5 (icon geometry and per-scene entities in ResolvedLook): Yes. The timeline stays self-contained, library updates cannot restyle old videos, and the page does not ship all of Lucide. Store only {viewBox, paths:[d], filled}, with size caps and the library version for provenance. Per-scene entities are also right for cache locality: a lesson-wide map in the global presentation slice would invalidate every chunk on any mapping change (chunks.py:208-211). Presentation.entity_colors stays the source of truth.

Q6 (engine_version 2): Bump it; it is part of the chunk key. The bump alone fixes nothing, though. The render job always rebuilds the timeline, while current_timeline serves stored builds, so it should also rebuild a Dynamic timeline of the current revision whose engine_version is below ENGINE_VERSION. The stage must keep rendering v1 timelines with B1 defaults for every new field, proved by a same-machine differential frame test, and must feature-detect rather than branch on the version.

Q7 (misses and errors): see 'missing'. The largest are:
- the transform determinism policy;
- presenter crop in the mediaPlan and extraction contract;
- event-based preflight sampling;
- a template tex() hook for MathJax and the entity-tint mechanism;
- a single source for slot geometry and type floors, and which side decides text fit;
- both content palettes for R1 templates on surfaces of the other mode;
- denormalising cross-scene data, for chunk-key correctness;
- a perf gate and re-running the §7.10 benchmark on the B2 templates;
- the safe-zone overlay named in the B2 scope;
- re-sequencing around a vertical slice.
