## What was built

**1. The demo phase** (workflow `wf_69f63c92-f23`, 10 agents). `direct.py` chooses a template per scene,
`events.py` writes the visual events, six more templates registered, `ENGINE_VERSION` 3 so stored Dynamic
timelines rebuild when served. One review, 7 findings, all fixed at the root.

**2. A generated lecture is Dynamic at all** (`aadhi/compose/dynamic/authoring.py`). Before this, a presentation
could reach a lecture only through an edit or an import, so a freshly generated lecture was always classic no
matter what the flag said.

**3. The look rotates** (owner decision in this session). The theme family (4 R1 families, two dark two light),
the personality (`crisp` / `soft`) and the hook kind, each from its own SHA-256 stream keyed off the lecture's
`look_seed` so they never move together; `look_epoch` re-rolls them for Fresh look / New colours while a plain
rebuild never does. The caption style and the cue style are **derived** from the chosen personality, which the
design's table already pairs them with — that also fixed a wrong stored value (a 9:16 Crisp lecture was storing
`clean_pill` captions where the design says `bold_outline`). `display_font` deliberately does **not** rotate:
`faces.resolver_fonts` maps a display id the B1 stage never drew to `outfit`, so rotating it would change the
stored look and nothing on screen.

**4. The Studio switch** (owner asked for it in this session). `models.AppSetting` (`app_settings`, migration
`0007_app_settings`) + `aadhi/runtime_flags.py` (5 s per-process cache, falls back to the environment whenever
there is no database to read) + `GET`/`PATCH /api/admin/settings` (admins only) + a **Video mode** panel on the
Studio's Administration page that also says which source is in force.
`compose.presentation.dynamic_enabled` is the single place the stored switch and `DYNAMIC_ENABLED` are merged, so
the API, the job workers and the compose layer always agree — no signature changed anywhere.

**5. Step 4** (workflow `wf_92dc5c5a-8b4`, 8 agents), re-prioritised by the owner mid-session from the original
template order (which would have converted one showcase scene) to the templates the fallback scenes actually
need: `full_bleed_media`, `animation_stage`, side-panel support in `worked_steps` / `key_terms`, `check`,
`predict`.

## Things found that are worth not re-discovering

- **The 9:16 builds could not be rendered at all** (step-4 review blocker). Dynamic preflight returned two
  blocking `text_overflow` findings on the portrait showcase. Fixed via `MEDIA_SPLIT_PHRASE_WORDS`.
- **The demo renderer was skipping preflight entirely** — it called `render_motion` directly, unlike the
  production path, which is how those broken portrait MP4s were produced in the first place. It now runs
  `run_preflight` + `raise_if_blocked`, with an explicit `--allow-preflight-blocks` escape hatch.
- **The CG-2 rule keeps biting:** a template's Python `fit` must refuse exactly what its JS `drawsScene` refuses,
  or the director picks it and the page silently draws `board_generic`. It caused the demo phase's D1
  (`worked_steps` unreachable for every generated worked example) and step 4's F1/F2 (`full_bleed_media` and
  `animation_stage` silently dropping a side panel). Check it for every new template.
- **Agents committed despite being told not to.** The demo phase's integrator made `a9e7f24` on its own. Check
  `git log` after a workflow, not just `git status`.
- **Adding a migration broke two existing tests** that pinned `0006` as head (`test_alembic`'s revision list, and
  two `test_review_migration` cases running `alembic check` at `0006`). Fixed at the root; `0007` has its own
  migration test.
- **The demo MP4s use synthetic media** — colour-bar test clips with a timecode burn-in — because no paid API is
  called. Fine for judging templates and layout; **not** something to show to people. A real demo needs a
  generation with real providers.

## How to turn it on

Studio → **Administration → Video mode** → on. Every lecture generated from then on is a Dynamic video; lectures
that already exist keep the style they were made with. `DYNAMIC_ENABLED` in the environment remains the default
when no switch is stored.
