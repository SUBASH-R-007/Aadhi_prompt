# 🧠 Aadhi EduEngine - Full Codebase & Architectural Context

This document is the **ultimate architectural blueprint** of the Aadhi EduEngine (KuttyKoncepts) codebase. It is generated through a deep analysis of all backend python files, the monolithic frontend `index.html`, database schemas, and edge-case rendering logic. 

---

## 1. System Architecture Overview

The system is designed as a dynamic, LLM-driven presentation engine that replaces static PowerPoint slides with a fully orchestrated, cinematic video experience. The stack is split into:
- **Backend:** A FastAPI server (`server.py`) handling JWT authentication, SQLite database management, and media generation proxying (Manim, TTS, AI Video).
- **Frontend:** A massive, monolithic `index.html` built with Vanilla HTML/JS/CSS that manages state (`window.slideSyncState`), orchestrates DOM updates based on audio timing, and parses LLM-generated JSON into real-time rendering.

---

## 2. Backend Deep Dive

### 2.1 Database & ORM (`models.py` & `database.py`)
The system uses **SQLAlchemy** connected to a local SQLite database (`projects.db`). The schema was recently strictly migrated to enforce user-based isolation.

**User Model (`users` table):**
- Features JWT-based authentication.
- Stores `username` (Unique) and `password_hash` (encrypted via `bcrypt` / `passlib`).
- Has a one-to-many relationship with the `projects` table (`back_populates="owner"`).

**Project Model (`projects` table):**
- Binds a generated presentation to a specific user via `user_id` (Foreign Key).
- Stores extensive metadata: `subject_name`, `unit_name`, `session_number`, `session_title`.
- Stores the entire LLM output as a raw text string in the `json_data` column.
- Tracks `created_at` and `updated_at`.

### 2.2 FastAPI Server (`server.py`)
The server acts as a robust middle-layer between the database, the frontend, and external generation tools.
- **Authentication Routes:** `/api/login` issues OAuth2 JWT Bearer tokens with a 7-day expiry.
- **Project Routes:** `/api/projects` securely fetches and saves the parsed JSON payloads, verifying the JWT via `Depends(get_current_user)`.
- **Manim Execution (`/run-manim`):** A POST endpoint that accepts raw Python code generated by the LLM. It writes this code to a temporary file (`temp_manim.py`) and executes a raw `subprocess.run(["manim", "-ql", ...])` to compile the video, returning the URL to the frontend.
- **AI Video API (`/generate-ai-video`):** A proxy endpoint that takes the LLM's highly detailed video prompt and forwards it to an external generative AI provider, returning the final MP4 URL.

### 2.3 TTS Generation (`run_tts.py`)
Handles the voice of the mascot (Aadhi). 
- Utilizes the `edge-tts` Python library to generate high-quality audio files dynamically. 
- Communicates back to the frontend to trigger the `[SYNC]` logic once the `.mp3` is fully loaded.

## 3. Frontend Deep Dive (`index.html`)

The frontend is a monolithic marvel of Vanilla JS and CSS, handling incredibly complex asynchronous state management.

### 3.1 The LLM JSON Contract (The Master Prompt)
Embedded in `index.html` is a massive system prompt (acting as the brain of the engine). It forces the LLM to output a strict JSON payload:
1. **Concept Map (`concept_map`):** A hierarchical map of learning objectives rendered visually using libraries like Vis.js.
2. **Scenes Array (`scenes`):** A sequence of slides containing:
   - `type`: Either `content`, `ai_video`, or `simulation`.
   - `html`: The actual text payload (enforcing zero-redundancy against the voiceover).
   - `narration`: The exact spoken script, peppered with `[SYNC]` tags.
   - `side_panel`: Identifies which dynamic interactive module to render (e.g., `chart`, `3d_model`, `terminal`, `manim`).

### 3.2 The `[SYNC]` Engine (Kinetic Typography)
This is the most complex piece of logic in the codebase, solving the cognitive split-attention effect.
- **Preparation:** When a slide loads, the engine uses `querySelectorAll('h2, h3, p, li, pre, .math-block')` to find all textual elements.
- **Descendant Filtering (Line 3779):** The engine iterates through the selected elements and checks their parent tree. If an element (e.g., `<li>`) is inside another tracked element, it is ignored. This ensures that the array of tracked DOM nodes matches the exact number of `[SYNC]` tags generated by the LLM.
- **Media Exclusion:** Crucially, the selector explicitly omits `img`, `table`, and `.board-image-placeholder`. These elements render immediately on screen, bypassing the sync engine so they don't consume `[SYNC]` tags meant for text.
- **Execution:** As the audio plays, the engine calculates the current playback time against the estimated character-timing of the text, removing the `cascade-hidden` CSS class exactly when the word is spoken.

### 3.3 Dynamic Slide Advancement (`window.slideSyncState`)
Because a slide may have a video playing, TTS audio, and math rendering all at once, the engine uses a robust state machine to determine when it is safe to auto-advance to the next scene.
- **`audioFinished`:** Set to true when the TTS audio fires its `onended` event.
- **`videoFinished`:** Set to true when an interactive simulation finishes.
- **Cinematic B-Roll Looping:** If an `ai_video` is just B-roll (no native audio), the engine smartly applies the `loop` and `muted` attributes. It then modifies `hasVideo` to false in the state machine, completely ignoring the video's length and relying 100% on the `audioFinished` flag to seamlessly cut to the next slide exactly when the voiceover ends.

### 3.4 Dynamic Side Panels
The engine can morph its layout in real-time based on the LLM's `side_panel` directive:
- **MathJax:** Auto-renders complex LaTeX formulas.
- **JSXGraph:** Renders interactive Cartesian coordinate plots and geometry.
- **Terminal:** Simulates a live hacker terminal typing out code.
- **3D Models:** Instantiates a `<model-viewer>` block to let students interactively spin 3D atoms, shapes, or biological models.
- **Chart.js:** Auto-renders animated pie, bar, or line charts based on LLM data.

## 4. Current State & Recent Architectural Fixes

If a new developer or AI is picking up this project, they must be aware of the following freshly implemented structural patches:
1. **SQLite Concurrency & Schema Drops:** The backend initially struggled with migrating the `user_id` foreign key. To resolve this, the old `projects_old` tables were manually dropped to allow SQLAlchemy's `Base.metadata.create_all()` to cleanly regenerate the exact schema required for JWT auth.
2. **Table/Image Sync Disintegration:** Previous builds attempted to synchronize tables and images using the `[SYNC]` engine. Because the LLM does not generate `[SYNC]` tags for these elements, it resulted in massive index shifts, causing text to trigger early and tables to remain permanently invisible. This was permanently fixed by omitting media tags from the tracker array entirely.
3. **B-Roll Deadlocks:** Fixed a critical bug where 5-second AI videos froze indefinitely while waiting for 15-second TTS audio to finish. The videos now natively loop in the background.

## 5. Next Steps for Development

- **Manim Sandboxing:** The `/run-manim` endpoint in `server.py` executes LLM-generated code directly via a subprocess. This must be wrapped in a secure Docker container or restricted sandbox to prevent arbitrary code execution on the host machine.
- **JWT Frontend Integration:** Ensure the UI logic in `index.html` fully leverages the new JWT routes, verifying that projects are saved strictly under the authenticated `user_id` and fetched accordingly.
- **Export to MP4 Pipeline:** Finalize the `autoExportRecorder` module in `index.html` using the MediaRecorder API to stitch the synchronized DOM, Audio, and Video states into a single, downloadable `.mp4` file for offline consumption.
